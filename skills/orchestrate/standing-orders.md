# Standing orders: defaults

The orchestrator uses these when no one has set their own. To override,
create `~/.agents/standing-orders.md` (every project) or
`.agents/standing-orders.md` in a project root (that project) and write only
the lines you change, under the same headings. Project beats user, user beats
this file. Do not edit this file: an update overwrites it.

## Models

- Orchestrator: the session's model. Coordinates only, writes no code.
- Implementer: the session's model.
- Reviewer: a different model from the implementer when one is available;
  otherwise the same model in a fresh context.
- Fallback after a usage limit: another available model of the same or a
  higher tier. With none left, wait for the limit to reset and retry; a limit
  never ends the session or waits on the user.

## Review

Every pull request gets one review against the project's checklist. It is
merge-ready when the implementer has verified it with the project's
`verify-*` skill, its checks are green, and the review is clean.

## Concurrency

Keep up to three implementers busy while that many independent tickets are
ready, plus their reviewers.

## Tracker

Update the tracker at every state change without being asked: claimed and in
progress at dispatch, in review with the pull request link, done after the
merge, back to todo with a comment when parked. With no tracker, the ledger
is the tracker.

## Merging

Never merge without an explicit ask in this session. Get every pull request
to merge-ready and list them.
